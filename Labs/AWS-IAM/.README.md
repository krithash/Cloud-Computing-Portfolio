# Architecture Description

AWS Identity and Access Management (IAM) was configured to securely manage access to AWS resources using IAM Users, IAM Groups, and IAM Roles.

An IAM User was created with AWS Management Console access and assigned permissions through AWS managed policies, allowing secure authentication into the AWS account.

An IAM Group was created to simplify permission management by assigning a common policy to multiple users. Any IAM user added to the group automatically inherited the group's permissions.

An IAM Role was created for Amazon EC2 with the **AmazonS3FullAccess** managed policy. The role was attached to an EC2 instance using an IAM Instance Profile, allowing the EC2 instance to securely access Amazon S3 without storing AWS access keys.

This implementation demonstrates AWS best practices for centralized identity management, secure permission assignment, and temporary credential-based access delegation.

# Project Overview

This project demonstrates the implementation of AWS Identity and Access Management (IAM) to provide secure authentication and authorization for AWS resources. IAM Users were created for console access, IAM Groups were used to simplify permission management, and IAM Roles were configured to securely delegate permissions to Amazon EC2 instances.

By assigning permissions using AWS managed policies and enabling EC2 instances to access Amazon S3 through IAM Roles, this implementation follows AWS security best practices such as Role-Based Access Control (RBAC), temporary credentials, and the Principle of Least Privilege.

# Implementation

## 1. IAM User Creation

Created an IAM User with AWS Management Console access.

### Activities Performed

- Created an IAM User
- Enabled AWS Management Console access
- Configured login credentials
- Attached AWS managed permissions
- Logged in using IAM credentials

### Outcome

Successfully created an IAM User capable of securely accessing the AWS Management Console with assigned permissions.

---

## 2. IAM Group Creation

Created an IAM Group for centralized permission management.

### Activities Performed

- Created an IAM Group
- Added IAM Users to the group
- Attached the AmazonS3FullAccess policy

### Outcome

Successfully configured a shared permission model where all group members automatically inherit Amazon S3 access.

---

## 3. IAM Role Creation

Created an IAM Role to provide secure access from Amazon EC2 to Amazon S3.

### Activities Performed

- Created an IAM Role for EC2
- Attached the AmazonS3FullAccess policy
- Assigned the role to an EC2 instance
- Verified role attachment

### Outcome

Successfully enabled EC2 instances to securely access Amazon S3 using temporary IAM credentials.

---

## 4. IAM Validation

Validated authentication, permission assignment, and role-based access.

### Activities Performed

- Logged in using the IAM User
- Verified group-based permissions
- Launched an EC2 instance with the IAM Role
- Confirmed Amazon S3 access through the assigned role

### Outcome

Successfully demonstrated secure identity management, centralized permission administration, and temporary credential-based access using IAM Roles.
