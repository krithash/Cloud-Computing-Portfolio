# Architecture Description

* A custom VPC named `MyVPC` was created with CIDR block `192.168.0.0/16`.
* An Internet Gateway named `MyIGW` was created and attached to the VPC.
* `PublicSubnet` was created with CIDR block `192.168.1.0/24`.
* `PrivateSubnet` was created with CIDR block `192.168.2.0/24`.
* Separate route tables were created for the public and private subnets.
* `PublicRT` was associated with `PublicSubnet`.
* `PrivateRT` was associated with `PrivateSubnet`.
* A default route `0.0.0.0/0` through `MyIGW` was added to `PublicRT`.
* The private route table does not contain a direct route to the Internet Gateway.
* An EC2 instance in the public subnet was configured with a public IPv4 address and private IPv4 address.
* An EC2 instance in the private subnet was configured with a private IPv4 address only.
* The public EC2 instance can communicate with the Internet when the route table, public IP configuration, and security rules permit it.
* The private EC2 instance cannot be directly reached from the Internet.
* Private instances can use a NAT Gateway or NAT instance for **outbound** Internet access when required.

# Project Overview

This project demonstrates the creation and configuration of a custom AWS VPC containing separate public and private subnets. Route tables and an Internet Gateway were configured to control network traffic. EC2 instances were launched in both subnet types to understand how AWS networking provides Internet connectivity and network isolation.

The lab provides practical experience with VPC architecture, CIDR addressing, subnetting, routing, Internet Gateways, EC2 networking, and public versus private network design.

# Implementation

## 1. Create VPC

Created a custom VPC to provide an isolated virtual network environment.

### Activities Performed

* Opened **VPC → Create VPC**.
* Name: `MyVPC`
* IPv4 CIDR Block: `192.168.0.0/16`
* Created the VPC.

### Outcome

Successfully created a custom VPC using the `192.168.0.0/16` IPv4 address range.

---

## 2. Create and Attach Internet Gateway

Created an Internet Gateway to provide Internet connectivity for resources in the public subnet.

### Activities Performed

* Opened **VPC → Internet Gateways**.
* Created an Internet Gateway.
* Name: `MyIGW`
* Selected **Actions → Attach to VPC**.
* Selected `MyVPC`.
* Attached the Internet Gateway.

### Outcome

Successfully created and attached `MyIGW` to `MyVPC`.

---

## 3. Create Public Subnet

Created a public subnet for resources that require direct Internet connectivity.

### Activities Performed

* Opened **VPC → Subnets → Create Subnet**.
* VPC: `MyVPC`
* Name: `PublicSubnet`
* IPv4 CIDR: `192.168.1.0/24`
* Created the subnet.

### Outcome

Successfully created `PublicSubnet` using the `192.168.1.0/24` address range.

---

## 4. Create Private Subnet

Created a private subnet for resources that should not be directly accessible from the Internet.

### Activities Performed

* Opened **VPC → Subnets → Create Subnet**.
* VPC: `MyVPC`
* Name: `PrivateSubnet`
* IPv4 CIDR: `192.168.2.0/24`
* Created the subnet.

### Outcome

Successfully created `PrivateSubnet` using the `192.168.2.0/24` address range.

---

## 5. Create Route Tables

Created separate route tables for controlling traffic from the public and private subnets.

### Public Route Table

* Opened **VPC → Route Tables → Create Route Table**.
* Name: `PublicRT`
* VPC: `MyVPC`
* Created the route table.

### Private Route Table

* Opened **VPC → Route Tables → Create Route Table**.
* Name: `PrivateRT`
* VPC: `MyVPC`
* Created the route table.

### Outcome

Two separate route tables were created to provide independent routing configurations for the public and private subnets.

---

## 6. Associate Subnets with Route Tables

Configured the subnet associations so that each subnet uses the appropriate route table.

### Public Subnet Association

* Opened `PublicRT`.
* Selected **Subnet Associations → Edit**.
* Selected `PublicSubnet`.
* Saved the association.

### Private Subnet Association

* Opened `PrivateRT`.
* Selected **Subnet Associations → Edit**.
* Selected `PrivateSubnet`.
* Saved the association.

### Outcome

The public and private subnets were successfully associated with their respective route tables.

---

## 7. Configure Public Route

Configured the public route table to send Internet-bound traffic through the Internet Gateway.

### Activities Performed

* Opened `PublicRT`.
* Selected **Routes → Edit Routes**.
* Added a new route.
* Destination: `0.0.0.0/0`
* Target: `Internet Gateway`
* Selected `MyIGW`.
* Saved the route.

### Outcome

`PublicSubnet` now has a route to the Internet through `MyIGW`.

---

## 8. Launch EC2 Instance in Public Subnet

Launched an EC2 instance in the public subnet to verify Internet connectivity.

### Activities Performed

* Opened **EC2 → Launch Instance**.
* Selected the required AMI.
* Selected the required instance type.
* Configured network settings:

  * VPC: `MyVPC`
  * Subnet: `PublicSubnet`
  * Auto-assign Public IP: **Enable**
* Configured a Security Group allowing SSH on port `22`.
* Launched the instance.

### Expected Network Configuration

The instance should have:

* A private IPv4 address.
* A public IPv4 address.
* A route to the Internet through `MyIGW`.

### Verification

After connecting to the EC2 instance:

```bash
whoami
```

Internet connectivity was tested using:

```bash
ping 8.8.8.8
```

The ping process can be stopped using:

```text
Ctrl + C
```

### Outcome

The public EC2 instance successfully obtained public and private IP addressing and was able to communicate with the Internet, subject to the configured routing and security rules.

---

## 9. Launch EC2 Instance in Private Subnet

Launched an EC2 instance in the private subnet to demonstrate private network isolation.

### Activities Performed

* Opened **EC2 → Launch Instance**.
* Selected the required AMI.
* Selected the required instance type.
* Configured network settings:

  * VPC: `MyVPC`
  * Subnet: `PrivateSubnet`
  * Auto-assign Public IP: **Disable**
* Configured the required Security Group.
* Launched the instance.

### Expected Network Configuration

The instance should have:

* A private IPv4 address.
* No public IPv4 address.
* No direct route to the Internet Gateway.

### Outcome

The private EC2 instance was isolated from direct Internet access.

A private instance can still be given **outbound Internet access** by adding a NAT Gateway/NAT instance in a public subnet and configuring the private route table to route Internet-bound traffic through it.

For administrative access, alternatives include:

* Bastion Host
* AWS Systems Manager Session Manager
* VPN

# Public vs Private Subnet

| Feature                          | Public Subnet                      | Private Subnet                               |
| -------------------------------- | ---------------------------------- | -------------------------------------------- |
| Direct route to Internet Gateway | Yes                                | No                                           |
| Public IPv4 address              | Can be assigned                    | Normally not assigned                        |
| Direct Internet inbound access   | Possible with proper configuration | Not directly possible                        |
| Outbound Internet access         | Through Internet Gateway           | Through NAT Gateway/Instance when configured |
| Typical Resources                | Web Servers, Load Balancers        | Databases, Internal Applications             |
| Internet Exposure                | Can be Internet-facing             | Isolated from direct Internet access         |

> **Important:** A subnet is considered public because its route table has a route to an Internet Gateway. Simply assigning a public IP to an EC2 instance does not by itself make the subnet public.
